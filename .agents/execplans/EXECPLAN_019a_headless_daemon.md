## Purpose / Big Picture


A daemon is a process that keeps running after its clients disconnect. After this step, a small program without a terminal screen can create a Carlos session over a private Unix socket, send text, watch a running tool, reconnect, and answer an approval. Another client can read the session or interrupt work while a send waits for the native backend. Closing the client leaves the session and backend alive.

The existing terminal remains embedded during this step: it still owns its session in process. EP019b will move all terminal workflows through the daemon and remove that path. This deliberate intermediate state ends at an owner review gate; it is not a second permanent terminal mode. This step does not build an iPhone app, network listener, language bindings, generic backend passthrough or every native terminal panel.

## Surprises & Discoveries


EP018a already supplies BackendWork values with no SessionState borrow, but its delayed-worker test constructs a fake Peer on the worker thread. The real ClaudeClient still holds a RefCell event handler and clients retain receiver fields. A mutex around the whole client would make an interrupt wait behind a blocked send. Source: `crates/carlos-core/src/backend.rs`, `claude_backend/mod.rs`, `codex_connection.rs`, and `session/command_work_tests.rs`.

The core still returns BackendUpdate, ClaudeUpdate, TurnUpdate, CommonUpdate and CodexClosed reports. Some fields describe shared facts, some describe one submitted command, and some tell the terminal to change its controls. SubmissionOutcome has no socket notification yet. The protocol also has both client_message_id and ClientOperation, while Entry.client_message_id remains null. These are known producer/consumer gaps, not an established deployed contract.

The core's one pending ordinary mutation is a useful order guard. The daemon must queue commands above it rather than returning Busy for every second client. Interrupts and approval answers need prompt service and separate validity checks; priority does not authorize an obsolete turn or a second answer to the same card.

The real Claude callback path held the transport selector lock across a controller call. The shared command adapter now clones one transport under a short lock and waits outside it. Claude interrupt bookkeeping still belongs to its caller's EventHandler; the caller prepares an opaque InterruptIntent and settles it after worker completion. Captured commands never borrow that RefCell.

Prepared work previously checked its session only after the call. A shared atomic retirement flag now lets a reset or dropped owner prevent work that has not started from writing at all. Work already dispatched still requires the existing checked completion and uncertain-outcome recovery.

Grok also held its process mutex through reply waits and wrote directly to a potentially blocked stdin pipe. GrokClient now keeps the child and receiver while GrokCommands holds a shareable I/O endpoint. A captured handle checks the native session revision even when rewind keeps the same id. Its writer accepts at most eight frames, eight MiB per frame and 16 MiB queued, and stops the owned child after a 500 ms write deadline. EOF rejects pending requests, and failed model changes no longer update the accepted settings cache. The tests initially expected post-interrupt transcript chunks that the real adapter correctly suppresses; they now prove control arrival by the peer releasing its withheld model reply only after session/cancel.

Installed Codex 0.167.1 accepts clientUserMessageId on turn/start and exports the same token as userMessage.clientId. A real binary driven by the local fixed-reply HTTP fixture proved it without an account or inference; artifacts are `/tmp/carlos-ep019a/native-echo-8g4keeq6/`. Initial thread/read checks raced native event creation and a second call returned list_turns unsupported; reading the actual item notification proved the correct field directly. Bind known private tokens to ClientOperation, never infer echo ownership from text.

The core now binds private UUID echo tokens to the registered ClientOperation. Native Codex userMessage.clientId and Claude prompt UUIDs select a known token; foreign tokens with equal text stay unowned. Grok binds the precise row it creates after acceptance. Sparse per-user ownership maps avoid adding a field to every stored transcript row. Delayed token binding emits a full replacement of that same row. A bounded pending-token set rejects further admission explicitly rather than growing forever.

The terminal suite after identity changes passed 176 workflows but exposed an overlapping-helper SQLite race during a second Claude fork: prompt-sources.ts opened the shared label database without any busy timeout. The screen correctly retained the failed edit, but the workflow should succeed once the earlier writer completes. Added a five-second SQLite busy timeout before WAL/schema setup and close a newly opened connection if setup fails. A separate-process lock test fails without this timeout and passes with it; TypeScript checks pass. Full terminal/native checks pass after the fix: 177 terminal workflows, 23 native-monitor workflows, the installed Codex contracts and 60 helper tests. Evidence: `/tmp/carlos-ep019a/m2-lock-terminal.log`. This is a real shared-database race, not an echo-text mismatch.

Priority controls now prepare immutable work without taking the ordinary send/fork/name slot. The owner claims any exact live card once, including a queued card without changing focus. A worker validates choices, bounded fields/forms and browser consent before writing. Definite validation failures reopen only that claim; uncertain native failures keep it claimed. Removing a card or replacing/dropping a turn clears its worker permission. The turn permission is allocated only when a control needs it. Control completions also check the owning logical session and native generation.

Claude callback replies belong to a helper process, not its conversation epoch. Captured callback replies now check helper identity without rejecting a still-live callback merely because that helper reset its transcript; send/rename/interrupt still check conversation epoch. Prepared ordinary work also checks the captured native generation before dispatch. BackendClient now requires Send (not Sync), so the daemon can transfer the backend owner to its session thread while its RefCell normalizer stays single-owned.

The first prepared controls checked permission only before the native call. Barrier-driven tests then proved the missing queue boundary: without a dequeue check, a retired frame still wrote. Codex, Claude and Grok now carry the same permission through the native writer queue and reject the frame before bytes are written, while preserving the healthy connection. Pre-call tests and native-writer tests cover distinct boundaries.

Grok's native reader used an unbounded mpsc sender, read_line buffer and stderr string. It now keeps facts charged through forwarding and owner handling, with sixteen MiB/4096 normal frames, one bounded terminal reserve, eight MiB per input frame and sixteen KiB of retained stderr. A producer may wait at most 500 ms for the owner to release queue space; cancellation releases that wait. Native init/open waits remain off the owner. LaunchCancellation registers the owned Grok process before waiting for initialize, so daemon shutdown can stop a launch that has not returned a client yet. Captured Codex/Claude/Grok handles also expose non-waiting cancellation hooks for the launch factories.

Bounding Grok history exposed an older startup problem: the embedded terminal waited for session/load before draining native events, then guessed that 250 ms was enough to collect the tail. Both daemon and terminal consumers now use one asynchronous open method and an ordered ready fact after history/tail adoption. The terminal can accept human text while load waits; the core queues it until ready. The native translator publishes the chosen thread identity before the first replayed item. A real owner test restores 6000 chunks through the bounded queue and dispatches the queued human prompt once; the terminal test checks its screen and ACP requests with the same workload. No second native prompt/history algorithm was added.

A full check also exposed a summary-test gate that waited for file existence, although the shell creates the calls file before printf writes its first byte. The assertion observed an empty file. The test now waits for nonzero length before asserting the single call. This changes the fixture barrier, not summary runtime behavior.

## Decision Log


Decision: split the old EP019 into EP019a, the headless daemon proof, and EP019b, terminal protocol coverage, shared client, cutover and deletion. Rationale: each ends in a working behavior the owner can review. Only the next ExecPlan is written in full; EP019b is scoped in `docs/terminal-client-migration.md` until this plan produces real interfaces. Date/Author: 2026-11-13, owner/Codex.

Decision: make real adapter concurrency the first gate, before sockets. Rationale: a working fake cannot prove a real Claude or Codex connection remains interruptible. Do not accept a lock held across an RPC reply wait as a solution. Date/Author: 2026-11-13, Codex.

Decision: keep the core mutation fence, add bounded FIFO admission above it, and handle interrupt/approval controls independently with their own turn/card/connection checks. FIFO means ordinary commands keep their arrival order. Already accepted native prompt queues remain backend-owned. Date/Author: 2026-11-13, Codex.

Decision: use ClientOperation as the sole semantic command identifier, with the daemon supplying the client identity. JSON-RPC request ids still pair one envelope with its reply, but are not send-retry identities. Before remote sends exist, replace random operation UUIDs with a per-client increasing, lossless decimal counter; SessionId and EntryId stay opaque. Rationale: a high-water mark lets the server reject expired retries without an unbounded UUID tombstone set. There are no deployed remote clients requiring compatibility code. Date/Author: 2026-11-13, Codex.

Decision: expose a fresh daemon-instance id in the greeting and retain logical session ids in the small registry. A new instance requires fresh snapshots and explicit recovery of uncertain commands, not automatic resend. Rationale: in-memory sequence/retry records do not survive a daemon restart. Do not claim exactly-once execution across a crash. Date/Author: 2026-11-13, Codex.

Decision: list saved sessions without starting their backends, then restore a dormant session once when a client subscribes. Rationale: the daemon must recover a saved logical id without launching every historical helper or creating duplicate helpers for concurrent subscribers. Save Ralph state for display/review, but require an explicit decision to resume it after a crash. Date/Author: 2026-11-13, Codex.

Decision: retain an explicitly named execute_embedded bridge for the terminal and old deterministic fakes while BackendWork::execute accepts only a shareable CommandHandle. Rationale: the worker route cannot accidentally capture the whole non-Sync client, and both routes reuse the same call/completion algorithm. EP019b deletes the embedded route. Date/Author: 2026-11-13, Codex.

Decision: authenticate reconnect with a private server-issued ResumeToken, separate from ClientId visible in shared rows. A retained identity with a wrong token fails rather than exposing private results. Return nullable next_operation at counter exhaustion while preserving reads. Rationale: visible ownership ids cannot double as credentials, and a maximum counter must fail without wrapping. Date/Author: 2026-11-13, Codex.
