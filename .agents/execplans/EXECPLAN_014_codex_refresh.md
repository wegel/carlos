## Decision Log

- Keep the native CLI as a child process. The official Rust client pulls in the
  Codex workspace and would couple Carlos to a particular Codex source version.
- Bound stdin work, pending calls, individual frames and UI events. A pipe
  failure closes the client, settles callers and sends one reserved fatal notice.
  Users can think indefinitely before answering a callback.
- Read a complete bounded snapshot before replacing history. Never silently
  install a truncated transcript. Preserve the older missing-terminal-turn
  workaround until real native fixtures establish when public pages replace it.
- Primary contract: <https://learn.chatgpt.com/docs/app-server.md> and schemas
  generated by the installed CLI. Later features remain out of Stage 1.

## Stage 1 implementation

- `protocol.rs` coordinates one installed native process. Separate state, reader,
  writer and event-budget modules own bounded pipe work and terminal closure.
- `initialize_client` sends the required `initialized` notice after success.
  Resume and fork request metadata with `excludeTurns: true`; normal reads omit
  turns. Public turn/item pages preserve native IDs and additive fields.
- The reader caps each frame at 8 MiB. Stdin holds at most eight queued frames
  and 16 MiB; at most 64 calls wait. Events remain charged until the UI handles
  them, including its intermediate queues, with caps of 4,096 frames and 16 MiB.
  One terminal diagnostic bypasses the normal budget.
- Request deadlines cover writing and waiting. Only known read methods can time
  out while keeping native work alive. Late read replies are discarded without
  retaining an unbounded ID ledger. Mutating timeouts stop the owned process.
  Callback/async writes have a separate two-second bound; users can think without
  a deadline. Async replies retain exact request parameters and native replies.
- A Codex-only closed flag fences late turns, items and approvals after terminal
  failure. Carlos keeps the human draft and stops Ralph automatic work.
- History reads share one deadline, normally 20 seconds, plus 64 MiB fetched JSON
  and assembled-history limits. At most 65,536 pages can be read. One-item pages
  prevent several large records from overflowing an otherwise valid wire frame.
- Legacy recovery remains read-only and runs only outside authoritative modern
  pages. It keeps server prefixes, metadata and item versions; joins exact
  turn/item IDs; and preserves raw-relative order without rewriting contradictory
  server order. Fork/removal markers make a raw file ineligible. An unreadable,
  malformed or oversized matching eligible file fails clearly.
