# Keep entry lookup and synthetic replay inexpensive

Carlos now checks an entry’s private counter against the first stored id before searching a hash map. The store accepts that shortcut only when both ids have the same namespace, the counter difference fits a local index, and the row at that index has the exact requested id. Entries outside that order retain the existing full-id hash lookup. Backend item, turn, prompt and approval references still store opaque EntryId values. Only the transcript store reads counters.

The store never scans old rows when appending or handling a key. It removes mapped exceptions when truncating, verifies turn-diff references against live rows, resets its seed when empty and trims deferred capacity hints. It retains no growing collection of retired ids. Reordered same-thread histories keep their proven ids and use the map where necessary. Existing full-row/id and alias invariants still run; the new invariant also checks every stored exception against its exact live row. A test-only middle insertion rebuilds its own index without adding work to runtime paths.

The synthetic fixture previously built an entire draft vector, then copied it into a second complete row vector while assigning ids. It now calls SessionState::transcript_append for each generated source row and reserves the known batch size first. That is the ordinary entry constructor, shared with production history/fork code; it still calls Transcript::append, allocates the real EntryId and updates the real row bookkeeping. The fixture neither forges ids nor skips the store. It preserves the original raw source rows without running the higher-level live read-label controller. The generated text, roles, kinds, paths, counts and benchmark output format remain unchanged. The old unkeyed adoption helper is now restricted to the fixtures that still need it.

Three new tests reject old ids after truncation and later appends, reject ids from another namespace with the same counter, and cover gaps left by approval cards both before and between rows. Existing native history, ambiguity, reminting, delayed update and generated-map tests pass. The synthetic reproducibility test now checks separate namespaces and each entry’s exact live position as well as the original content checks.

The integrated tree passes 1,005 Rust tests, 174 terminal workflows, installed Codex 0.167.1 contracts and 23 native monitor workflows. All 3,000 comparison streams match f40386c at 51,390 checkpoints with no panic; pre-plan output retains only its same 103 classified differences. The isolated staged tree also compiles without the pending reconnect move and passes its 10 transcript tests. Format, whitespace and size checks pass.

The primary agent checked namespace/counter arithmetic, gaps, foreign/retired ids, map retirement, same-thread reorder and the unchanged constructor path using the engineering reviewer prompt. Findings: none. Verdict: PASS. No subagent or independent reviewer ran.

The first speed runs showed an additional bulk-loading cost. We retained every raw run and then ran 15 serial samples per executable on CPU 6, alternating which executable ran first. Those samples compare the original pre-plan binary, the pending reconnect tree before these fixes and the final tree. The intermediate tree’s apply median was 14.71. Final paired apply changes vary in both directions (median +0.07 ms); one isolated +5.97 ms sample remains in the recorded data. The other 14 range from -0.74 to +0.31 ms. No repeatable slowdown remains in total replay or drawing, and the small apply difference is within the observed run variation. The small fixture’s replay/draw medians are 0.99 / 0.98 and 0.48 / 0.48. All runs have the expected 6,001 messages and 39,347 lines, including the benchmark’s final appended row. The zero RSS fields remain unusable.
