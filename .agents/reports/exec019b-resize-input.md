# EP019b resize and queued keyboard input

The final large-source check exposed lost keyboard readiness in Crossterm 0.29.0. Its Unix reader could return a resize before reading a keyboard token in the same batch. The unread End bytes then waited until another key arrived. A private diagnostic reproduced the failure for ANSI and Markdown: originals and layout counts were complete, while End reached the handler only when cleanup sent Ctrl+C. The original keys.log proves eventual handling, not handling during the failed forty-second wait.

The repair enables Crossterms existing use-dev-tty feature. That selects its level-triggered Unix reader, which checks currently readable input and handles the keyboard descriptor before resize. Both backends retain the same rule for choosing a terminal descriptor: stdin when it is a terminal, otherwise /dev/tty. Windows uses its separate source. The [pinned feature list](https://docs.rs/crate/crossterm/0.29.0/features) documents the flag and its filedescriptor/rustix dependencies. Cargo.lock adds only filedescriptor 0.8.3; libc, thiserror and winapi were already locked. No application viewport, queue, thread, timer or parser is added.

The Unix integration test initializes a real Crossterm reader on a PTY, queues SIGWINCH synchronously, then writes End while the reader waits on a separate control socket. No later terminal key can rescue a lost wakeup. The old backend fails with only resize after 0.26 seconds. The chosen backend passes eight fresh batches. Tests retain finite startup and event deadlines. Source-size checks stay within 399 lines per file and 60 per function.

The existing large-source fixture also had an early empty-composer predicate: it could match the screen before /tools full ran, then read a file that had not yet been saved. It now waits for the same empty composer and exact saved tool_output==full under its original wait. The immediate resize-to-End gesture, forty-second viewport deadline, colors, private typing, exact clipboard SHA and reconnect assertions remain unchanged. The clean private combined 64 MiB ANSI/16 MiB Markdown run passes in 14.592 seconds.
