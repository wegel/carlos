# Milestone 3 review fixes

The reader still translates native records. `ClaudeClient::handle_event` still runs the turn-end rules on the handling thread. No commit, installation, dependency, toolchain change, or edit under `.agents/` or `docs/` was made. The two UI fixture files already had edits when this task began; those edits remain.

## Findings

1. **Repeated reset key.** The reader cleared its live/history cursors for a reset that the app suppressed. `event_live.rs` now checks `new_conversation_id` before clearing either cursor. Both reader and handler advance the transport epoch before checking that key, matching main's controller guard. `repeated_reset_key_keeps_two_distinct_transcript_rows_through_dispatch` uses real helper pipes, the receiver, queue rules, handler, and app. It asserts two rows and ids `claude-msg-0-1-0` and `claude-msg-0-2-0`, and rejects a stale handler result. The terminal test is `test_claude_repeated_reset_key_keeps_both_replies`.
2. **Pending calls behind terminal bytes.** A final sender held the batch permit while waiting for consumer acknowledgements; the reader waited for that permit before reading EOF. `event_batch.rs` now queues subsequent terminal notices behind the current sender without blocking the reader. The queue keeps the 1,024-record/8 MiB bounds; EOF/error work has reserved access. `event_emitter.rs` rejects pending synchronous calls when it stops the helper. `transport.rs` checks the stopped flag again under the pending-request lock. `transport_reader.rs` still rejects unanswered calls before publishing EOF. The real-pipe test `pending_call_is_rejected_before_terminal_notices_or_bytes_are_acknowledged` holds the reader at a barrier, fills the byte budget, produces stderr/callback cancellation/closed/EOF, checks the exact closed-before-reply error before releasing the reader, and reaches EOF without acknowledgements. It then checks error, callback-cancelled, closed order. No sleep or elapsed-time guess establishes that bound.
3. **Fatal SDK translator errors.** `event_live.rs` now ignores live translator errors after retaining the preceding native side effects. Controller errors still stop the helper. `malformed_sdk_delta_is_ignored_and_pending_call_receives_success` covers absent, null, and wrong-type indices. `invalid_controller_frames_reject_pending_calls_and_report_fatal_error` covers a bad version, an invalid init UUID, and a missing reset UUID. The terminal test is `test_claude_malformed_sdk_delta_keeps_the_session_usable`.
4. **UI teardown.** The server forwarder used to own the only cancellation callback while blocked in `recv()`. `EventReceiver<T>` now lets the forwarder move that callback to the UI receiver. Dropping the UI receiver therefore closes the backend's byte budget directly. Files: `backend.rs`, `event.rs`, `app/input_forwarders.rs`, and forwarder test support. `dropping_ui_receiver_cancels_budget_through_production_forwarder` moves a charged line into the actual UI queue, defers EOF, drops the UI receiver, and waits for the final sender to finish without acknowledging bytes.
5. **Obsolete queue predicate.** `input_queue_rules.rs` no longer guesses backend identity from `generation` and `epoch`. `native_completions_follow_prompt_and_item_facts_in_real_dispatch` replaces the synthetic queued-completion test. It sends native frames through a real receiver, prioritizes with a budget of two, invokes `process_event`, and asserts transcript order, final status, and empty accepted-prompt state. `input_dispatch.rs` only widens that function's visibility to sibling app tests.

## Exact error split from main

- `claude_sdk_events::main_items` used `if let Ok(output) = translate_claude_line(...)`. Every error from **live SDK record translation** was ignored. Native usage/notices/init/binding/thinking side effects before that call still happened. Unknown additive records and unsupported block/delta kinds retained the translator's existing tolerances. The same rule now lives in `EventNormalizer::items`.
- `transport_reader::Reader::run` stopped the helper for unreadable/invalid JSON or a controller envelope whose `v` was not 1. `ConversationGuard::route` errors were also fatal: missing reset event UUID; empty/overlong reset UUID after the duplicate/session guards; incomplete/overlapping reset transition; held reset frames beyond 1,024 frames/8 MiB; invalid init session UUID; resumed session mismatch without a reset permit. These guards remain unchanged. Queue overflow still stops the helper. Synchronous calls are rejected independently of final-event delivery.
- `claude_session_history::{receive,read_chunk,append_record}` propagated history page/chunk/base64/JSON/session/translator errors to `claude_control_replies::receive`, which showed the error and closed the **app query**. Main retained earlier records from that page and did not kill the controller merely for a bad history record. The backend now emits the retained facts followed by a failed `claude/controlReply`; it keeps serving synchronous calls. A failed native history reply must also reach the app, rather than disappearing when the reader closes its own delivery queue.
- Controller request failures retain their separate rules: `start`, `sessions.info`, and `sessions.read` close the app query; `task.stop` stores its error for the exact task/run; `context` settles its optional read; `usage.optional` errors are ignored; other failed controls show their error. A synchronous unsuccessful reply fails that call with the native message or `Claude SDK request failed`.
- Native `unsupported_dialog` remains a warning. Other native `error`/`transport_error` records close the query. SDK result errors remain visible system rows and complete owned prompts only after native idle. Main reports unexpected EOF even after another error, unless any accepted controller envelope carried `event: closed`, including an unknown frame type. The reader now preserves that exact rule.
