# Native settings and terminal editor checks after the owner split

The terminal no longer needs to own a Codex session to check its settings editor. Twelve native cases now call the real Core settings reducer, startup installer and guarded prompt writer. Six terminal cases use an actual Device with an accepted client snapshot and the real private editor. No test recreates AppState or adds a backend route.

The ten old codex_settings_tests cases retain future/live write order, captured active turn, native method parameters, newer external settings, queued choices, retired root/epoch replies, unsupported-method fallback, advertised models/efforts, ordinary prompt inheritance, native error code/data, and omission of invalid or unsupported prompt overrides. Native notices are asserted from SettingsUpdate.effects instead of an old frontend transcript append. The actual settings terminal workflows still check visible errors and saved files.

The four old codex_startup_settings_tests cases now split at the real owner boundary. Core checks resumed native model/effort and unknown summary without a write, explicit resumed detailed summary, and deliberate concise summary for a new thread. Both deliberate writes use exact thread/settings/update parameters after the real reconnect completion forwards initial choices. Device checks two open/close cycles with Use thread setting, a model-only edit that omits unknown summary, and an explicit auto-summary choice. Accepted shared facts remain unchanged and no editor-only case allocates a client operation.

The mixed rejected-settings cases retain exact rejected/high editor values across an actual catalog replacement. The actual daemon rejection workflow now selects chosen/high, verifies that both values survive rejection and close/reopen, and checks both explicit native writes exactly. The invalid-effort case retains the private attempted value and unchanged accepted low value; Core rejects that typed choice before native writes or persistence. The daemon now owns that validation, so no duplicate terminal-native catalog validator is added.
