# EP019b native reader tests

The daemon owns the native reader after the terminal cutover. Ten existing real-pipe tests now drive engine::Native::start, the actual bounded daemon bridge, instead of the terminal's obsolete UiEvent forwarder. The tests keep the original helper scripts, correlation IDs, deadlines, queue budgets and causal barriers. A local guard calls Native::stop on teardown; it adds no runtime code or alternate event reader.

Seven order tests preserve both idle/result orders, accepted/rejected interrupts, a later conversation reset or second prompt, a reader running ahead of the handled cursor, byte/frame saturation with an unanswered interrupt and 4096 rejected requests after EOF. Three shutdown tests retain pending-call rejection before byte acknowledgement, bridge teardown while the byte budget is full and visible later stderr chunks after the first closes the query. Exact completion order, native turn IDs, retained byte charge, empty waiter/completion queues and helper failure status remain asserted.

All ten tests pass privately in0.50s on the real daemon bridge. Strict all-target Core Clippy passes. The largest test file has216lines and its longest function has46lines; the shutdown file has136lines and its longest function has55lines. The local helper has138lines. The draft is /tmp/carlos-ep019b/root-goal-panel and is now joined for its normal branch hook; the exact original terminal-only modules retire in the same commit.

The two old input_codex_order tests describe the removed terminal/native queue: keyboard events were placed first and only terminal-close diagnostics bypassed that queue. The new terminal never receives native facts. Native::start preserves their order in its bounded channel; the migrated reset/second-prompt tests assert those native positions. Existing test_daemon_terminals_keep_drafts_private_while_native_control_releases_a_held_send checks actual terminal responsiveness while a native write waits. Existing reconnect and closed-state terminal workflows check private drafts and close diagnostics through the daemon. No synthetic UiEvent ordering adapter will remain after deletion.
