# Keep consent and hints on each actual terminal

The old `view_ownership_tests.rs` mixed a native session owner with a terminal view and fake backend. The new checks give Core its native target checks and give the actual Device a greeted client plus accepted plain facts. No replacement type combines a Core session with a terminal view.

- `review_ownership_ctrl_l_must_preserve_session_status`, `review_ownership_first_allow_must_preserve_request_facts`, `every_local_hint_and_first_consent_leave_all_session_fields_unchanged`, and `native_answer_editors_keep_session_facts_until_they_send_an_answer` now run through `remote/questions_ownership_tests.rs::first_consent_and_local_hints_leave_every_accepted_shared_fact_unchanged`. It checks all accepted header, entry, approval, goal, queue, task, settings and sequence fields before and after consent and Ctrl+L. It covers three backends and five neutral input shapes: plain decision, fields, form, browser and unsupported. The Device creates zero operations. The Core native callback/response tests retain backend-specific parsing and exact answer envelopes.
- `duplicate_adoption_keeps_initial_guidance_and_second_accept_but_clears_extra_lines` splits at the real boundary. Core `identical_drafts_keep_only_the_active_card_and_queue_moves_keep_their_own_ids` preserves native addresses. Device `new_opaque_card_cannot_inherit_old_consent_while_duplicate_metadata_keeps_it` preserves confirmation for duplicate facts and drops it for a new address. Device question tests retain drafts and confirmations through readonly progress and late preflight errors. The removed AppState-only extra-hint list and its old overlay buffer hash have no live caller.
- `queued_and_retired_copies_cannot_reuse_an_armed_card_id` now has the explicit Core successor `queued_and_retired_copies_receive_new_addresses_when_adopted`, with both original branches. A queued or retired copied draft gets a fresh address; the copied address is not an active answer target. The Device test above proves that a fresh address cannot inherit consent.
- `retired_card_cannot_return_through_queue_focus_or_answer_a_reused_native_id` now runs directly on Core as `retired_native_request_cannot_return_through_either_queue_or_answer_a_reused_id`. Both queues refuse the retired address, including after a native ID is reused; a guarded stale answer writes nothing, while the current replacement writes exactly once. The actual terminal workflow `test_replacement_helper_requires_two_accepts_for_its_own_request` retains the second-consent and exact native callback envelope assertions.

The frozen `src/tests/fixtures/m4_view_expected.json` remains byte-for-byte unchanged. Its SHA-256 is `fbec966010fefa822d1d50669ba549c67d4d05966bd37e831594b3e2101867dc`. It holds273 old overlay cases:210 artificial backend/kind combinations,14 native-field sequences,49 actual Codex method sequences. Each of seven tails has39 cases. The old test compares the legacy overlay's whole-cell hash together with native calls, pending native ID and local confirmation. The separate helper test only checks that this removed comparator rejects shortened arrays.

The old273-case comparator is retired with the embedded overlay, rather than rebuilt around another frontend session owner. Its original JSON stays as historical evidence; current results must never regenerate its hashes. The active checks cover its clauses as follows:

- `accept` and `decline`: Core native callback/response contract tests check exact supported envelopes and stale-target rejection. The actual workflows `test_codex_concurrent_approval_kinds_keep_their_own_wire_responses`, `test_claude_plan_approval_shows_native_plan_and_never_sends_an_extra_prompt`, and `test_claude_decline_cancel_and_unsupported_form_never_invent_answers` retain actual screens and native writes.
- `other`: the Device ownership matrix, local question editor tests and `test_claude_default_no_question_names_ctrl_s_and_ignores_y_on_review` keep arbitrary local keys from submitting native answers or changing shared facts.
- `focus` and `arrive`: Device `two_devices_cycle_focus_without_changing_shared_active_cards_or_other_drafts`, `tail_first_card_events_follow_the_active_card_until_the_user_explicitly_focuses`, and `unknown_resolution_keeps_both_actual_device_drafts_and_explicit_focus` preserve independent focus and drafts. The Codex concurrent child and daemon two-terminal F4 workflows check real native routing.
- `cancel` and `resolve`: Device exact-card receipt/retirement tests and Core live-address checks preserve other drafts and reject stale targets. The Claude browser-decline/cancel and unsupported-form phone workflows check the actual envelopes and visible actions.

Core's separately migrated20,000 fixed-seed approval sequence model still exercises all ten original request kinds, queue moves, duplicate facts, response failures, and retired/foreign/unallocated addresses. The separate frozen native approval-lifetime oracle belongs to the callback worker and remains required. These checks are not a claim that the new Device paints the removed whole-overlay hashes; actual terminal screen and wire tests prove the supported workflows.
