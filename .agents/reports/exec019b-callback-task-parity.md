# EP019b callback and task parity follow-up

This developer slice repairs existing callback and task workflows found by the ordinary deterministic terminal suite running through the actual daemon. It does not approve EP019b, switch startup defaults, delete the embedded terminal or install a binary. The owner prohibited further reviewers until the end of EP019b; this slice used no reviewer.

## What changed

- The terminal follows the actual first active callback when the daemon publishes an ordered batch from its tail. Explicit F4 focus and edited private drafts stay pinned. When a selected blocking card retires, the terminal advances to its next blocking card without reopening a hidden nonblocking answer.
- Plain plan cards receive the shared editor's Page Up and Page Down keys. Browser cards retain the existing explanation that consent does not prove browser completion. Reserved decision keys stay inside the card even when a native request does not offer that choice.
- Key traces hide only the focused secret field or secret review. A hidden question no longer hides the ordinary composer from the optional key trace.
- The existing bounded native form worker publishes a checked schema error for its exact live callback. The optional `Approval.input_error` stays within 2048 UTF-8 bytes. A late checked error keeps the original schema, opaque target, private answer and confirmation; it disables acceptance without replacing the draft. The terminal strips absent null defaults through the shared cheap field helper. It adds no schema compilation to card creation or paint.
- Claude answers obey the helper's existing JavaScript-safe integer range before a native write. Codex keeps Rust's exact integer range. A typed known helper rejection reopens only the same still-live claim; generic native errors and uncertain writes remain uncertain.
- Captured Codex response handles may answer the exact current transport's initialize callback during reconnect. Ordinary calls, reads and forks still require initialize to finish, including at their writer guard. Generation, stopped-state and transport-pointer checks remain on every reply.
- Claude process tasks keep their public task/run identity across a native conversation reset in the same helper. Their prepared native write still carries its original root permission. A later matching acknowledgement settles only its original private operation. New helper generations retire old identities. The owner retains at most eight pending task stops across resets. Typed pre-write retirement is a rejection; uncertain writes keep an explicit no-automatic-retry notice.
- The owner reports Approval only while an actual blocking card remains. A completed root with only nonblocking questions reports Idle while preserving its cards and F4 count.

`Approval.display_id` restores the old Request caption. The core escapes and clips it to 4096 UTF-8 bytes before exporting it. This readonly caption is separate from the opaque `Approval.id` used by commands. Neither the terminal nor the core parses a caption into a command address. A focused test supplies a native caption shaped like a valid opaque ID, proves it cannot address the card, and proves the issued opaque ID can. Client tests enforce both caption and checked-error byte bounds. Existing no-native-route tests still check every other exported field and assert the exact caption separately.
