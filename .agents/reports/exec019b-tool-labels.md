# Shared AI labels and host preference writes

Commits `4634d90`, `f1d34c6` and `c1f4c9a` reuse the existing atomic preference writer, serialize ui-settings.json updates under one file lock and connect the existing summary worker to real daemon sessions. The daemon owns generated labels and the host AI-label default. The terminal keeps themes and tool-output display choices. No second settings database was added.

settings/tool-labels/set takes the session, original private operation, expected settings revision, explicit enabled boolean and optional save-default flag. A stale revision changes nothing. The existing summary code cancels old jobs, restores literal/known labels and preserves original source bytes. An optional disk write captures that same boolean and uses the existing ordinary worker. If the disk write fails, the live accepted change remains and the requesting client receives a bounded notice. New and lazily restored sessions reload the host flag; existing sessions retain their accepted value.

The daemon now starts the existing SummaryService during an actual native launch. Its completed-label queue wakes the owner; no terminal label worker or extra worker pool was added. The existing queue/cache/native-result checks remain. Optional Create.tool_labels applies only on first launch when a terminal explicitly provides its environment override. Attach does not change it, old callers may omit it and the six-field session catalogue does not store it.

The shared preference helper preserves unknown fields and valid symlinks. It rereads and merges under the retained sibling .ui-settings.json.lock, waits at most two seconds off the owner and publishes through the existing same-directory atomic writer. Theme writes remove the old layout key as before. The terminal appearance writer does not save the daemon's AI-label boolean.
