# Terminal workflows the daemon must preserve

EP018a inventories the terminal before EP019 moves it behind a socket. The current terminal calls SessionState directly; those calls are temporary. Version 1 covers basic conversation facts and commands, not the whole terminal. Names below describe proposed typed command families, not methods already implemented in carlos-proto. EP019 must define their Rust request/result types and exercise them through its real dispatcher before deleting the embedded path.

## Work that stays on the device

- The composer, unsent text, input-history cursor, rewind selection, retained draft list and confirmation token belong to each client. See `src/app/view_state.rs`, `state_input.rs`, `claude_edit_view.rs`, `state_approval_view.rs`. Commands carry submitted text and an originating client operation id. A result may describe accepted or rejected submitted text; it cannot instruct every editor to clear itself.
- Wrapping, Markdown rendering, colors, scroll, auto-follow, selection/copy, help, panel visibility, selected row, collapse policy and `/tools` stay local. See `render_transcript.rs`, `render_sections.rs`, `input_events_clipboard.rs`, `tool_output_command.rs`, `tool_output_items.rs`. Expanding remote output starts a bounded output watch; collapsing stops it. A client keeps only its own cached pieces.
- Goal, queue and model editors, question answers not yet sent, browser consent and task-panel navigation stay local. See `codex_goal_state.rs`, `codex_queue_state.rs`, `codex_settings_view.rs`, `claude_question_state.rs`, `claude_tasks.rs`. The core validates the final command against current shared facts.
- Dictation stays local, including capture, Whisper, endpoint timing, text insertion and device preferences. See `state_dictation.rs`, `input_events_dictation.rs` and the optional dictation modules. It produces ordinary submitted text; no audio dependency enters core, protocol or shared client.

## Shared facts and explicit commands

- Conversation rows, reasoning, commentary, diffs, labels and completion already use snapshots/history and numbered session events. See `core_events.rs`, `state_items.rs`, `state_transcript.rs`, `state_summaries.rs`. The daemon owns backend item keys, summary jobs, native history, row ids and turn boundaries. Remote clients never call append/upsert or choose backend replay offsets.
- Send/steer/queue mode uses `session/send`; add an explicit send policy and command correlation before cutover. See `input_events_submit.rs`, `turn_submit.rs`, core `prompt_commands.rs`. Preserve human-before-automatic priority, exact text, accepted UUID binding, local echo and uncertain-send behavior. Retrying an operation must not submit twice. A queued submission needs its originating client id through dequeue and recovery.
- Interrupt uses `session/interrupt`. See `turn_interrupt.rs`, core `turn_interrupt.rs`. Preserve matching-turn checks and backend callback interruption. A successful request does not claim the backend stopped.
- Approvals, permissions, browser consent, plan exit and structured questions use `session/approve` plus live cards. See `turn_approval.rs`, `native_questions.rs`, `codex_reply.rs`, `claude_browser.rs`, `claude_question_input.rs`. Validate offered choices and typed answers against the current card; one answer wins across clients. Callback focus is local: provide explicit focus/read commands only where they affect backend polling. Card retirement clears only a matching client's confirmation token.
- Ralph uses `session/setRalph`, but its status facts must also expose queued toggles, waiting and continuation state used by the terminal. See `state_ralph.rs`, core `ralph_commands.rs`, `turns.rs`. Keep markers, prompt-file reads and timers daemon-owned; do not create a competing automatic driver while native goals run.
- Session naming needs typed `session/rename {name}` with accepted saved-name facts. See `session_name.rs`, core `name_commands.rs`. Preserve native name changes, Claude session identity and failures without clearing another client's composer. The local `/rename` parser remains local.
- Earlier-prompt edits need `session/rewind {entry,text,operation}` and prompt-anchor facts. See `turn_submit.rs`, `claude_rewind.rs`, core `rewind_commands.rs`, `input_history.rs`, `claude/edit.rs`. Resolve the selected stable id inside the core. Preserve Codex/Grok fork history, Claude startup/acknowledgement, unknown-source prompts, queue safeguards and failed-edit recovery. Backend ids and native fork positions stay private.
- Native task/agent panels need typed task-list/detail/history reads and `task/stop {task,expected_run}`. See `codex_panel.rs`, `codex_panel_text.rs`, `codex_task_status.rs`, `claude_task_view.rs`, core `codex/panel_*`, `claude/tasks*`. Export stable task addresses scoped to the session/connection, not unrestricted native JSON. Preserve root/child routing, old-page reads, bounded output, run identity checks and unavailable/unknown states. Several clients can request different task details.
- Native queue needs `queue/read`, `queue/add`, `queue/edit`, `queue/delete`, `queue/reorder`, `queue/start`, with typed payloads, stable queue ids, explicit expected input/revision and targeted recovery. See `codex_queue.rs`, `codex_queue_receive.rs`, core `codex/queue*.rs`. Keep attachment-rich input opaque and noneditable where current checks reject edits. Preserve uncertain writes, read-before-automatic-work and exact single dispatch. Local queue mode, selected record and recovery editor do not become session state.
- Native goals need `goal/read`, `goal/set`, `goal/clear` and complete known/unknown/pending/error facts. See `codex_goals.rs`, `codex_goal_view.rs`, core `codex/goals*.rs`. Root mutations require explicit user commands; ordinary chat and child-task views cannot create or resume a goal. Preserve the Ralph conflict check and explicit active-goal consent.
- Model/effort/reasoning-summary settings need `settings/read`, `settings/set` and capability/current/pending/rejected facts. See `codex_settings.rs`, `codex_settings_draft.rs`, `claude_models.rs`, core `codex/settings*.rs`, `claude/settings*.rs`, `runtime_settings.rs`. Validate advertised choices, preserve inherited unknown values and save host defaults only after acceptance. Distinguish host session defaults from a device's display choices. Native live-update support and its narrow legacy fallback remain in the backend adapter.
- Context, quota and usage notices already partly use SessionInfo; add typed detailed quota/context/compaction facts for existing panels. See `claude_context.rs`, `claude_quota.rs`, `rate_limits.rs`, `claude_notices.rs`, `render_status.rs`. Poll timers belong to the daemon; a device computes elapsed/reset countdowns from timestamps and issues an explicit compact command. Never infer another backend's quota.
- Reconnect/resume/create and backend closure need daemon lifecycle commands and connection status facts. See `backend_setup*.rs`, `codex_reconnect.rs`, core `codex_connection*`. Preserve native connection generations and history adoption. Closing a terminal detaches it; only explicit session stop closes backend work. Client reconnect must not create a second native process or restart turn timers.
- Summary preferences and worker results need typed settings/facts, not client-side transcript edits. See `state_summaries.rs`, core `summary_*`, `summaries/`. Keep original tool bodies, accepted label provenance and cancellation checks. Host cache writes belong to the daemon.
- Launch cwd/backend/Ralph choices, saved session lists and resume choices belong to daemon create/resume/list requests. Device config and terminal startup flags stay local. See `crates/carlos-core/src/session/mod.rs`, `src/runtime/mod.rs`, `src/app/backend_setup*.rs`. The daemon must reject unsupported capabilities explicitly rather than silently hide a terminal feature.

## Backend work and read interests

The session owner prepares a command and applies its completion. A transport worker executes a prepared call without borrowing SessionState; neither socket writes nor reply waits belong in the owner loop. Connection/turn/operation guards must reject stale completions. The in-process terminal may call the same execute step synchronously until EP019 changes its transport.

EP018a implements `prepare_turn_text`, `prepare_rewind_text` and `prepare_rename`, a consuming `BackendWork::execute`, then `finish_backend_work`. These methods replace the old blocking core send/fork/name entry points. A Busy result preserves unsent human text; a stale completion returns recoverable text with an explicit uncertain-outcome error and never retries. A reset retires the old slot without letting its completion clear a new one. Early consumed/completed Claude facts cannot duplicate an echo or revive a completed turn.

A prepared work value is Send and owns no SessionState borrow. This does not make the existing BackendClient universally Sync: Claude still keeps its native normalizer in RefCell, and clients retain receiver fields. EP019 must move each receiver/normalizer to its proper owner and pass generation-bound transport handles to workers. Capture the matching handle before dispatch; do not execute old work against a replacement helper. Prove this with real deterministic native adapters in the first daemon milestone, including a reset before dispatch and a reply after reconnect.

Current backend waits to audit at daemon entry points:

- Prompt start/steer and rewind/fork (`prompt_commands.rs`, `rewind_commands.rs`), naming (`name_commands.rs`), approvals and interrupts (`approval_reply.rs`, `turn_interrupt.rs`, `codex/callback_commands.rs`). Preserve uncertain-write semantics; do not blindly retry after a timeout.
- Launch, native resume/history and reconnect (`crates/carlos-core/src/session/mod.rs`, `protocol_history*.rs`, `codex_connection*.rs`). These belong to lifecycle workers, not the owner thread.
- Deferred backend actions (`backend_actions.rs`), Claude context/settings/task controls and Codex panel/queue/goal/settings reads use existing asynchronous request/reply tokens. Keep those tokens and deadlines. The daemon must schedule any remaining blocking convenience wrapper outside its owner loop.
- Session rename/defaults, Ralph prompt reads, summary jobs/cache and transcript-history reads can touch the filesystem. Prepare immutable work and settle checked results; never hold the session while waiting for disk or a child.

A read interest is a client's explicit request for a task list, a task's details or a control's current facts. It is not panel visibility or focus. EP019 aggregates active interests across connections and routes each reply by its original target/generation. One client's selected task cannot determine another client's accepted reply. Disconnection removes that client's interests without cancelling another client's work.

## EP019 gates and deletion order

1. Build the owner loop, session manager and Unix listener with bounded command/output queues. A headless client creates/resumes a session, sends text, observes a running tool, reconnects at both cursors and races an approval. It must also read state while a backend command waits.
2. Extend provisional version 1 with the typed families above. Test two clients with different editors, read targets and pending commands. Check malformed/stale requests, unsupported backend capabilities, late completions, queue overflow and uncertain writes. Avoid a generic backend method/JSON escape hatch.
3. Introduce the pure Rust shared client for greeting, reconnect, numbered facts, paged-history merging, output cursors and correlated local echo. Keep platform sockets and UI policy outside it. Add language bindings only when EP022 packages the phone consumer; generate schemas only when a consumer needs them. Add a timed delta merger only after socket measurements show a need.
4. Drive every existing deterministic terminal workflow through the actual daemon dispatcher. The preserved tests are the parity checklist: prompts, approvals/questions/browser consent, native controls, queues/goals/settings/tasks, edit/fork recovery, names, Ralph, transcript/copy and dictation feature modes. Assert screens and backend requests, not only shared-client state.
5. Delete the terminal's embedded SessionState/backend launch path in a separate commit after parity passes. The terminal must not retain a privileged direct-core route for features missing from the wire. Re-run release terminal/contract checks and socket perf comparisons against the accepted pre-split executable before owner review.

EP018a implements the output read and cleans the pre-socket core boundary. EP019 owns the actual daemon, scheduler, command dispatcher and terminal cutover. No entry in this inventory claims those components exist today.

## Checks after the workspace split

Cargo and rustc now enforce the package/module boundary. Core has no terminal dependency; a client cannot add inherent SessionState methods through aliases or write its private fields. Real compile-fail doctests exercise those rules. `scripts/check-core-dependencies.py` checks resolved package names, including aliases, dev/build edges, every feature and inactive platform branches. It rejects terminal/audio packages below core and permits only reviewed serde packages below proto.

EP018a removes the earlier source tokenizer/module walker and its synthetic Rust fixtures. Its pre-workspace file lists, identifier guesses and alias parser no longer provide the package guarantee. Ordinary builds compile declared modules; dependency checks cover declared packages even on inactive targets. Review still checks semantic rules that the compiler cannot express, including keeping client editor policy outside core and I/O out of protocol types. The repository does not claim that a lexical scan proves those rules.
