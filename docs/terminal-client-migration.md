# Terminal workflows the daemon must preserve

EP018a is complete and accepted. EP019a proves the daemon with headless clients; EP019b moves the terminal behind its socket. The default terminal still calls SessionState directly; those calls are temporary. The opt-in consumer, `carlos --daemon-socket PATH resume LOGICAL_SESSION_ID`, reads actual daemon facts through carlos-client and shares the existing lazy renderer/composer. It attaches an existing logical session and supports bounded source transfers with one worker that owns the complete active original. Actual64MiB ANSI and16MiB Markdown cases preserve early/late rows, colors, private input, reconnect and exact original copying. Cross-window selection matches the old terminal's bytes in both directions. See `.agents/reports/exec019b-live-source.md` for evidence and the remaining extreme Unicode memory cost. Latest and older task pages, queue and goal panels work; local dictation also uses the shared terminal view. Child workflows, settings, startup and other parity checks remain open. Keep the deletion gate below. Version1remains provisional. Names below include proposed command families; EP019b must define each remaining typed request and test its real consumer before deleting the embedded path.

See `src/app/view_state.rs`, `state_input.rs`, `claude_edit_view.rs`, `state_approval_view.rs`. Commands carry submitted text and an originating client operation id. A result may describe accepted or rejected submitted text; it cannot instruct every editor to clear itself.

See `render_transcript.rs`, `render_sections.rs`, `input_events_clipboard.rs`, `tool_output_command.rs`, `tool_output_items.rs`. See `codex_goal_state.rs`, `codex_queue_state.rs`, `codex_settings_view.rs`, `claude_question_state.rs`, `claude_tasks.rs`. The core validates the final command against current shared facts.
- Dictation stays local, including capture, Whisper, endpoint timing, text insertion and device preferences. See `state_dictation.rs`, `input_events_dictation.rs` and the optional dictation modules. The socket adapter and embedded wrapper now share the same local view methods, capture ids and cancellation. It produces ordinary submitted text; no audio dependency enters core, protocol or shared client. See `.agents/reports/exec019b-dictation.md` for checked behavior and untested microphone/inference limits.

## Backend work and read interests

The session owner prepares a command and applies its completion. A transport worker executes a prepared call without borrowing SessionState; neither socket writes nor reply waits belong in the owner loop. Connection/turn/operation guards must reject stale completions. The in-process terminal may call the same execute step synchronously until EP019b changes its transport.

EP018a implements `prepare_turn_text`, `prepare_rewind_text` and `prepare_rename`, a consuming `BackendWork::execute`, then `finish_backend_work`. These methods replace the old blocking core send/fork/name entry points. A Busy result preserves unsent human text; a stale completion returns recoverable text with an explicit uncertain-outcome error and never retries. A reset retires the old slot without letting its completion clear a new one. Early consumed/completed Claude facts cannot duplicate an echo or revive a completed turn.

A prepared work value is Send and owns no SessionState borrow. This does not make the existing BackendClient universally Sync: Claude still keeps its native normalizer in RefCell, and clients retain receiver fields. EP019a must move each receiver/normalizer to its proper owner and pass generation-bound transport handles to workers. Capture the matching handle before dispatch; do not execute old work against a replacement helper. Prove this with real deterministic native adapters in the first daemon milestone, including a reset before dispatch and a reply after reconnect.

Current backend waits to audit at daemon entry points:

- Prompt start/steer and rewind/fork (`prompt_commands.rs`, `rewind_commands.rs`), naming (`name_commands.rs`), approvals and interrupts (`approval_reply.rs`, `turn_interrupt.rs`, `codex/callback_commands.rs`). Preserve uncertain-write semantics; do not blindly retry after a timeout.
- Launch, native resume/history and reconnect (`crates/carlos-core/src/session/mod.rs`, `protocol_history*.rs`, `codex_connection*.rs`). These belong to lifecycle workers, not the owner thread.
- Deferred backend actions (`backend_actions.rs`), Claude context/settings/task controls and Codex panel/queue/goal/settings reads use existing asynchronous request/reply tokens. Keep those tokens and deadlines. The daemon must schedule any remaining blocking convenience wrapper outside its owner loop.
- Session rename/defaults, Ralph prompt reads, summary jobs/cache and transcript-history reads can touch the filesystem. Prepare immutable work and settle checked results; never hold the session while waiting for disk or a child.

A read interest is a client's explicit request for a task list, a task's details or a control's current facts. It is not panel visibility or focus. EP019b aggregates active interests across connections and routes each reply by its original target/generation. One client's selected task cannot determine another client's accepted reply. Disconnection removes that client's interests without cancelling another client's work.

## Checks after the workspace split

Cargo and rustc now enforce the package/module boundary. Core has no terminal dependency; a client cannot add inherent SessionState methods through aliases or write its private fields. Real compile-fail doctests exercise those rules. `scripts/check-core-dependencies.py` checks resolved package names, including aliases, dev/build edges, every feature and inactive platform branches. It rejects terminal/audio packages below core and permits only reviewed serde packages below proto.

EP018a removes the earlier source tokenizer/module walker and its synthetic Rust fixtures. Its pre-workspace file lists, identifier guesses and alias parser no longer provide the package guarantee. Ordinary builds compile declared modules; dependency checks cover declared packages even on inactive targets. Review still checks semantic rules that the compiler cannot express, including keeping client editor policy outside core and I/O out of protocol types. The repository does not claim that a lexical scan proves those rules.

EP019a's rebase onto main a29b1a1 also preserves Ctrl+M's context-size editor. Its draft lives in RuntimeSettingsView; carlos-core::context_preferences stores one saved JSON choice per backend. EP019b must expose that host default through typed settings reads/writes, keep attached Codex's size read-only, preserve Claude's shell override, and apply saved sizes only when opening a native process. A context-size choice is distinct from the live token-usage indicator. The daemon catalogue still has only its six session fields; this rebase does not add a second settings database.
